# symcc 性能与 Ctrl+C

在原分支 `codex/fork-shell-native` 原目录实施；没有创建 worktree，没有修改 CPU/ISA。

## 性能测量

工作负载是在目标系统启动后通过 shell 创建以下源码，运行 `symcc test.c -o test && ./test`，观察到程序输出 `test` 时停止。
前后使用相同键盘脚本、32 MiB RAM/DiskA 和模拟器指令计数；不是宿主编译耗时。

```c
#include <stdio.h>
int main(void){printf("test\n");return 0;}
```

| 版本 | 目标指令数 |
|---|---:|
| 优化前 | 8,723,272,704 |
| 只优化堆分配器 | 3,195,177,984 |
| 最终加入 Ctrl+C 软件检查点和取消边界保护 | 3,978,405,888 |

最终版本减少 54.39% 指令，约为原版的 2.19 倍速度。包含软件取消开销，不能用只优化堆的 2.73 倍替代最终结果。
日志在 `build/profile-exact.txt`、`build/profile-after.txt`、`build/profile-verified.txt`；采样阶段分类以 1024 条指令为粒度。
最终约 30.60 亿指令在 sld、8.88 亿在内核；性能仍有进一步改善空间。

原链接阶段 malloc 约占 43.3 亿指令，整链表合并约占 11.3 亿。分配器改为按大小组织空闲块，维护物理相邻块的双向关系和尾指针。
分配不再遍历所有已分配块，释放只检查相邻块；分裂、realloc、分配失败保护与外部 brk 留出的间隙均有回归覆盖。

软件检查点保留少量开销；只在每 4096 次函数入口/循环/goto 检查时进入内核。剩余主要成本是链接器的文本解析和符号字符串查找。
32 MiB 总 RAM 不会直接缩短这些计算，用户进程窗口仍为 2 MiB。

19 MHz 是游戏的时钟频率，不保证每周期执行一条指令；即使按每指令一周期计算，数十亿指令仍需数分钟。
这些模拟器计数能比较版本，不能替代实际游戏秒表测量。
按每指令一周期估算，最终工作负载在 19 MHz 下约 3.49 分钟；游戏实际可能更慢。

最终阶段内存（字节）如下，峰值来自原生阶段回归中的实际提交堆：

| 阶段 | loaded | BSS | 堆峰值 | 栈保留 | 合计 |
|---|---:|---:|---:|---:|---:|
| scpp | 236849 | 675 | 71760 | 65536 | 374820 |
| scc1 | 442044 | 912 | 97672 | 65536 | 606164 |
| sld | 209348 | 156 | 1369032 | 65536 | 1644072 |

三者均在 2097152 字节用户窗口内。更大的源码仍可能耗尽窗口，不能据此承诺所有任务都能编译。

## 取消机制

- 提示符：清除当前输入，显示 `^C`，返回提示符。
- heredoc：取消整份命令及临时正文，不打开或截断输出目标。
- 前台程序：终止整个前台进程树，返回状态 130；同一列表的剩余命令不执行。
- symcc：子阶段被终止，驱动保留一次清理机会；删除临时文件，保留旧输出，返回 130。
- 程序启动前的 fork 交接也传递取消请求；已收到取消的驱动不能再创建子阶段或发布输出。

编译器在对象中留下保留标签，用户链接器把标签展开为软件检查。内核/历史镜像仍把它们当零长度标签。
SDK 用户 C 程序保留 r12 作为计数寄存器，进程上下文保存/恢复该寄存器；生成器 `scripts/gen_platform.py` 负责实际系统调用桥。
没有检查点的旧程序和手写汇编，只能在系统调用处响应，不提供完整 POSIX 信号机制。

## 回归与交付

性能回归 `test_small_stdio_program_instruction_budget` 在旧版本耗尽 40 亿指令预算，在优化版本完成原生编译和运行。
主机分配器测试覆盖碎片、耗尽、重分配数据保持与独立 brk 间隙。
`shell_test --interrupt` 覆盖左右 Ctrl 事件、普通输入、四种死循环、等待输入的 cat、heredoc 和取消后的命令列表。
`--interrupt-native` 在目标机器内编译并取消新程序；`--interrupt-compiler` 取消链接，检查原 echo 仍能执行且临时文件清理。
独立审阅发现并补测两个边界：在 rename 调用前排队的 Ctrl+C 必须先于发布生效；内建命令中取消必须阻止后续命令。
`--interrupt-publish` 用直接帧缓冲就绪标记安排取消，验证旧程序保持；`--interrupt-builtin` 验证取消 help 后目录不被后续 cd 改变。
两项均先在未修复版本失败，再在修正版本通过；主调度器在系统调用副作用前轮询，shell 在命令间消费取消状态。
CLI 另测 ASCII ETX，避免只验证模拟的组合键。

最终完整回归结果见 `build/optimization-interrupt-verified.log`。实际游戏的键盘组合键和本次速度仍需用户复验；上一版容量配置导致的乱码已由用户确认修复。
最后一次 `mingw32-make test` 退出码为 0，包含全部既有模式、五项 Ctrl+C 专项、分配器回归、5 项原生运行库、8 项原生编译器、21 项 CLI 及镜像/平台测试。
标准 printf 小程序的独立端到端预算回归消耗 3,993,513,984 条指令，在 4,000,000,000 的预算内；该脚本与上面的 heredoc 采样负载不同，不混作同一组对比。
交付 zip 包含四个 32 MiB 镜像、加载说明、支持范围、验证记录、峰值内存、指令计数和 SHA-256 清单；打包器逐字节检查所有归档项。

C 功能与已知限制见 [支持范围](../symcc-c-support.md)。
