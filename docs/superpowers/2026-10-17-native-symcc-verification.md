# 原生 symcc 与 32 MiB 系统验收

交付日期：2026-10-18。功能代码基线 `46a5994`，分支 `codex/fork-shell-native`。
在项目原目录实施，没有创建 worktree 或整项目副本。

## 已验证的结果

最终 `mingw32-make test` 退出码为 0。命令从源码重建历史 M3、交互内核、用户程序、SDK、原生编译阶段和容量探针。
工具链、内核启动、进程切换、寄存器恢复、文件系统损坏检测、终端与 shell 所有原有模式均保留并通过。
新增 Python 验收包括镜像几何 2 项、平台布局 1 项、高数据区 2 项、原生运行库 5 项、原生编译器 7 项、CLI 20 项。

- shell 连接符 `&&`、`||`、`;` 与退出状态；整行解析后执行；跳过的 heredoc 消费正文且不打开重定向目标；`reset` 清屏并保留目录。
- RAM / DiskA 默认各 33554432 字节；用户窗口 2097152 字节，8 个进程槽，快照范围恰好结束于 RAM 上界。
- MINIX 32 MiB 根盘使用四个 zone bitmap；合法旧 8 MiB 镜像仍可挂载。分别在 8 / 16 / 24 MiB 以上写入、sync、保存、重启读取、删除，并独立检查分配位、超级块、原程序及填充文件。
- 独立探针的正常寻址、RAM 回绕、DiskA 回绕及同时回绕四种情况全部通过；所有测试位置原值恢复。目标指令数分别为 268771 / 268907 / 268915 / 269057。
- 真实客户机通过 heredoc 创建源码，运行 scpp → scc1 → sld，再加载生成 SPX；单源 `symcc` 连续编译两个不同程序，支持 `-o`、默认 `a.out` 和自定义 `-I`，保存磁盘后重启运行成功。
- 语法错误、缺头文件、未定义符号、选项错误、超长名字、输出目录不存在、磁盘写满、宏展开耗尽堆、格式化分配失败、数组/结构体/栈帧/链接尺寸溢出均明确失败，保留旧输出，不执行 `&&` 右侧命令。
- 32 位无符号运算覆盖运行时、全局常量和 `#if`；包括 0xffffffff、右移、除法与混合有符号比较。

## 独立审阅与修正

一次独立整分支审阅检查了原计划 Review Focus；审阅未修改项目文件。
四项问题均先用客户机测试复现，再修正：无符号常量类型丢失；聚合尺寸累加回绕；宏展开 realloc 失败后继续写入；格式化分配失败未传递到对象写出结果。
磁盘写满时发布截断 SPX 的问题也有独立失败/修复回归。修复后运行最终完整回归，没有用再次审阅替代测试。

实施中的调整：提前加入可配置模拟器指令预算；展开桥接复制循环以降低 2 MiB 快照成本；动态分配汇编标签表、几何增长对象行缓存、去掉客户机对象注释并按真实编码大小分配缓冲；分阶段执行现有编译核心；修正嵌套 for 声明、静态局部符号、二维数组声明及字符串转义问题。

## 游戏人工验收

模拟器验证与游戏验证分开记录：旧版 shell 的用户截图不能证明本次原生编译器或 32 MiB 高位寻址已在游戏通过。
先将独立 capacity-probe.bin / capacity-disk.bin 接入 RAM / DiskA，确认两项 32M PASS；再切换 kernel.bin / rootfs.bin，各设 32 MiB、Big endian。
观察详细启动日志、Welcome 后清屏、目录提示符与退格/Shift 符号，按 README 的 heredoc → symcc → ./main 流程操作，最后 sync 并保存盘后重启。

当前边界：MINIX 每个名字最多 14 字节；8 个合作式进程；2 MiB 进程窗口和 64 KiB 保留栈；没有硬件内存保护。
不含真正 64 位整数、浮点、完整 POSIX/GNU 库、管道/后台作业/完整 shell 展开、自动文件系统迁移；rename 保证同一文件系统普通文件的命名空间替换，不保证断电恢复。
上述边界与批准的设计一致。实际游戏容量、键盘和运行速度仍待人工复验。
