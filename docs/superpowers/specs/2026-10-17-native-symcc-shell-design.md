# 命令连接、reset 与原生 symcc 设计

日期：2026-10-17。状态：用户已确认设计，实施计划待审阅；本文件不代表功能已经实现。

## 目标与已确认约束

用户要求先修复截图中的 `cd temp && ls`，再将 symcc 移植进游戏，并增加 `reset` 清屏命令。
用户进一步允许将 RAM 和 DiskA 放宽到 32MB 或更大，以验证外部 bin 的容量。

验收目标：游戏启动进入 shell，能够输入、保存 C 源码，执行
`symcc main.c -o main && ./main`，由客户机内的编译、链接、加载过程生成并执行程序。
沿用 SymphonyPlus CPU/ISA、大端、DiskA MINIX 和 SPX 可执行格式。在当前项目原目录编辑，使用 Git 分支，不创建 worktree。

首版以 32MiB RAM + 32MiB DiskA 为默认候选配置；容量必须由高地址与别名检测确认。
宿主模拟器测试和真实游戏测试分别记录。外部文件变长不作为游戏硬件已支持该容量的证据。

## 现状与缺口

- `user/bin/sh.c` 会拒绝引号外的 `&`、`|`、`;`，也不保留外部命令的退出码供条件执行。
- 已有 cd/pwd、独立外部命令、重定向及 heredoc；本次扩展这些现有流程。
- 现有 symcc 的词法、预处理、语法、代码生成、对象与链接核心在 `symcc/src/`，汇编编码在 `emu/`。
- 客户机 libc 缺少堆分配、FILE、格式化 I/O 和编译器需要的字符串/数值转换接口。
- 当前 512KiB 用户窗口、8MiB 快照上界及硬编码的桥接/exec 地址需要统一配置。
- DiskA 驱动与镜像生成器按 8MiB 工作，bitmap.c 只使用第一个 zone 位图块。
- MINIX v1 的 zone 编号为 16 位。32MiB、1KiB zone 可表示；不能仅改变镜像文件长度而保持旧位图布局。

## 路线选择

采用“移植已有核心 + 客户机驱动程序 + 有界运行库”，必要时分阶段运行。
不重新实现一个与现有 symcc 无关、仅识别示例源码的编译器，也不通过宿主程序或预先编译结果替代游戏内编译。

优先将预处理、编译和链接分别作为客户机阶段：阶段间使用临时文件，进程退出释放该阶段的堆。
命令行入口保持 `/bin/symcc`，内部阶段细节不要求用户操作。
复用现有 Token、AST、codegen、Obj 与指令编码，保留宿主工具及旧测试接口。
如果实测单程序可以在预算内运行，允许合并阶段；判断依据是目标机器镜像大小和峰值内存，不能按宿主 exe 大小猜测。

## 32MiB RAM 配置与容量探针

默认候选布局如下，地址范围右端不包含在内：

| 范围 | 用途 |
| --- | --- |
| `0x0000000..0x0100000` | 内核、低地址网关、帧缓冲及原启动栈；继续校验内核链接上界 |
| `0x0100000..0x0180000` | 块缓存 |
| `0x0180000..0x0200000` | 常驻 syscall 上下文与内核栈；上下文位于低端，栈从高端向下增长 |
| `0x0200000..0x0400000` | 2MiB 活跃用户窗口 |
| `0x0400000..0x0600000` | exec 校验与暂存区 |
| `0x0600000..0x0602000` | exec 参数字符串暂存，保持当前 8KiB 限额 |
| `0x1000000..0x2000000` | 8 个 2MiB 用户快照，保留 8 个用户进程槽 |

使用统一配置生成/消费 RAM、用户窗口、上下文、内核栈、exec 和快照地址，消除 Python 桥接与 C 代码的重复常量。
fork 的内存隔离、指针检查、exec 事务性及八槽耗尽/恢复必须在新布局重新验证。
较大窗口会增加合作式切换的复制成本，记录目标指令数，不用减少测试或进程槽掩盖开销。

提供独立容量探针和独立测试磁盘，在约 8MiB、16MiB 和 32MiB 边界验证：

1. 读取并保存待测位置原值；向相距高地址位的位置写入不同模式。
2. 验证每处读回值，并确认低地址值没有因高地址写入而改变。
3. 还原原值，屏幕分别报告 RAM/DiskA 容量及是否发生地址别名。

探针不挂载或修改用户正在使用的文件系统，使用单独生成的测试磁盘。
游戏内实际探针结果由用户确认，模拟器通过只证明模拟器的地址范围。
默认系统 RAM 镜像按所选容量补零并输出容量信息，方便外部文件加载。

若各编译阶段的代码、BSS、峰值堆和栈实测无法容纳 2MiB，先消除无界缓存与重复分配。
用户已允许更大内存，必要时可使用 64MiB RAM、4MiB 用户窗口、8 个 4MiB 快照；所有区域重新由同一配置计算并通过边界测试。
DiskA 首版固定 32MiB，不随 RAM 自动升级文件系统格式。

## 32MiB DiskA / MINIX

32MiB 磁盘使用 32768 个 1KiB zone，按实际几何计算 zone 位图块数与首个数据区。
对于 128 个 inode、1 个 inode 位图块、4 个 zone 位图块，inode 区从第 7 块开始，首个数据 zone 为 11。

- 分配/释放按位号选择 `s_zmap[bit / 8192]`，再访问块内对应位；校验位图块数量与索引。
- 元数据解码、镜像生成、独立镜像读取器及损坏镜像测试都根据超级块定位 inode/数据，不能继续固定使用 4096/zone 8。
- 容量验证覆盖跨 8192、16384、24576 zone 的分配、释放、读写和重启持久化。
- 保留先前元数据 zone、间接块和删除/截断的合法范围检查。
- 可以继续挂载合法的旧 8MiB MINIX 镜像；构建新版 rootfs 会生成新镜像，不能把旧文件简单补零视为扩容或数据迁移。
- 32MiB 以上的磁盘需单独处理 MINIX v1 上限；本阶段不承诺任意大磁盘。

## Shell 命令连接与 reset

词法阶段区分 `&&`、`||`、`;`，不将引号内或反斜杠转义的符号当作连接符。
简单命令的文件重定向绑定到该命令。先完整解析整行，语法错误不执行前半条命令或截断文件。

执行语义：

- `a && b`：a 状态为 0 才执行 b。
- `a || b`：a 状态非 0 才执行 b。
- `a ; b`：完成 a 后执行 b。
- `&&` 和 `||` 优先级相同且从左到右求值，`;` 分隔命令列表；状态为最后实际执行命令的状态。
- cd/pwd/help/reset/exit 在 shell 中执行。cd 失败、语法错误、重定向失败必须为非零，外部命令从 waitpid 状态解码退出码；找不到命令为 127。
- 被短路跳过的命令不打开/创建重定向文件、不 fork。整行完成语法检查后，先按语法顺序收集全部 heredoc，再执行命令列表；跳过分支的 heredoc 也须消费并清理，正文不能成为下一条命令。
- 单独的 `&`、单独的 `|`、首部或连续连接符、尾部 `&&`/`||` 报语法错误；允许末尾 `;`。
- `exit` 尊重条件执行，允许 `exit N` 供退出状态验证，省略参数使用最后状态；非数字/参数过多报错。
- `reset` 无参数，向当前标准输出发送控制台清屏及光标归位序列，状态为 0；保留 cwd、磁盘、进程和设备状态，不重新启动内核。普通终端使用时清屏后显示当前目录提示符。

首版继续采用 256 字节输入行、每命令最多 32 个参数、整行最多 64 个 token、16 条简单命令及 8 个 heredoc。
整行超限时不执行命令；已经开始收集的 heredoc 发生资源错误时消费到对应结束标记并清理。
命令连接不是管道或后台任务。

## 原生运行库与 SDK

为编译器提供有界的 malloc/calloc/realloc/free、字符串/内存函数、ctype、整数转换、FILE 和格式化输出。
堆从镜像 BSS 末尾开始，通过平台 brk 或等价受检机制增长，必须与保留栈/参数区域分离。
realloc/free 需要实际复用空间；不能用无限增长的分配器应付 Obj 的逐行增长。
修改对象/文本缓存的增长策略时保留宿主语义，测试分配失败、整数溢出、文件短读/短写及关闭行为。

客户机编译器使用独立兼容头文件。SDK 至少提供 stdio.h、stdlib.h、string.h、stddef.h、stdarg.h、stdint.h、stdbool.h 和需要的 ctype/limits 接口。
用户程序支持当前 symcc 的 32 位整数 C 子集，验证函数、局部变量、循环、条件、指针和字符串。
标准输出至少支持 printf 的 `%d/%u/%x/%c/%s/%%`、putchar、标准语义的 puts。
SDK 的标准 puts 自动换行；不得改变现有 shell 所用“不自动换行”的 puts 约定。通过独立运行库或明确包装隔离两种接口。

现有宿主核心用 int64_t 保存字面量/内部表达式，而目标编译器的 long long 为 32 位。
必须明确改造客户机内部整数抽象、范围检查和格式化 ABI，不能仅把 int64_t typedef 为 int 后宣称语义正确。
首版承诺 signed/unsigned 32 位，显式检查超范围字面量、尺寸与地址计算；覆盖 `0xffffffff`、负数、符号/无符号比较和常量边界。
仅用于宿主的真实 64 位数据编码可以保持宿主实现；客户机不支持的 64 位功能须明确报错。

## 客户机 symcc 接口与产物

默认入口：`symcc source.c -o program`，默认输出 a.out；支持头文件搜索路径与单源文件编译/链接。
可复用现有核心提供 `-E`、`-c`、`-S`，但核心验收是默认全链路输出可执行 SPX；没有实现的选项报错，不静默忽略。
编译器读取 DiskA 上的源码和 SDK 文件，使用客户机文件系统写入中间产物及最终文件。
输出使用当前用户地址布局的 SPX，链接客户机启动代码、系统调用桥、整数运行库和 SDK 所需符号。
通过 chmod 或等价受检接口设置执行权限，生成的普通文件必须能被 execve 实际加载。
失败返回非零、诊断写入 stderr，临时文件关闭/删除；成功替换输出前完成编译链接，失败不破坏已有可执行文件。
命名遵守 MINIX 14 字节文件名限制，临时文件用独占创建并防止不同编译进程互相覆盖。
生成后的程序、源码及必要元数据 sync 后可保存磁盘，重启仍能执行。

## 验收证据

必须运行既有完整测试，并增加实际目标指令执行的验证：

- 用户截图流程：mkdir/cd/ls，`cd temp && ls` 正确使用变化后的目录；失败 cd 不运行右侧。
- `&&`、`||`、`;` 的混合求值、失败状态、未知命令 127、带引号符号、短路分支的重定向副作用、跳过命令的 heredoc 消费。
- reset 清空先前内容并归位，当前目录仍保留，后续命令正常；原详细启动日志和 Welcome 后清屏保持。
- 32MiB RAM 与磁盘高地址/别名探针，跨位图块的分配/释放和保存后重启读取。
- 客户机 heredoc 创建 `#include <stdio.h>` / `int main(){return 0;}`，原生 symcc 编译，生成 SPX 在另一进程执行。
- 带 printf、函数、循环、条件、字符串的程序打印唯一结果，宿主仅注入按键和观察屏幕，不能代替编译或解释命令。
- 语法错、未定义符号、缺失头文件、堆耗尽/文件错误会非零退出，`&& ./main` 不运行旧输出；已有输出内容保持。
- 同一 shell 连续编译多个不同源码，验证没有残留状态或临时文件/描述符泄漏；保存磁盘后重新启动运行生成程序。

测试结果区分：宿主构建成功、客户机模拟器原生编译/执行通过、实际游戏高地址探针与编译操作通过。
当前仅完成设计，不能将上述验收用例写成已经通过。
