# M4–M6：fork、DiskA 文件系统与交互 shell 设计草案

日期：2026-10-17
状态：用户于 2026-10-17 审阅通过；进入实施计划阶段

## 用户目标与验收范围

用户要求继续推进 SymphonyPlus 的 Linux 0.11 移植，实现 fork，并在启动完成后提供可交互 shell。
用户进一步明确：首版必须包含磁盘文件系统、ls/cat 和外部程序加载。

保留现有 CPU 电路与 ISA、8MB RAM、8MB DiskA、大端指令和数据、96×40 文本屏幕。
无 MMU、无硬件中断，采用合作式调度。游戏内最终验收不能由模拟器测试替代。

完成标准：加载 kernel.bin 和 rootfs.bin 后启动到提示符；键盘输入可编辑并回显；
shell 用真实 fork/exec/wait 执行从 DiskA 文件系统读取的 /bin/ls、/bin/cat 和演示程序；
父子进程的栈和可写全局变量隔离；退出后回收资源并返回提示符；输出超过屏高时正常滚屏。

## 已确认的源码现状

- init/main.c 在打印 Boot complete. Halting. 后返回；crt0 和链接器提供 halt 自跳。
- kernel/fork.c 的 sys_fork 调用 copy_process 时传入全零上下文及槽号 0，不具备可用 fork 语义。
- include/linux/sched.h 的 switch_to 为空操作，段基址与限长操作也为空操作。
- include/unistd.h 的 _syscall0…3 总是失败。
- 原 mm/memory.c 仍依赖页表，不能直接用于无 MMU 的进程地址空间。
- 键盘和时钟指令已定义，但模拟器目前始终返回零，未实现输入注入或磁盘镜像装载。
- 控制台已能输出启动日志，内核还保留 MINIX 文件系统与块缓存代码。
- 链接器的低地址池未显式避让 0x2000…0x2eff 帧缓冲；crt0 清屏会覆盖这一区间。
  当前启动测试通过不能证明被覆盖的其他跳转仍安全，必须在扩大运行范围前消除此重叠。
- 2026-10-17 执行工作区已有六套测试程序全部通过；这不是重新编译后的测试结果。

## 路线比较与选择

1. **推荐：固定用户窗口 + RAM 快照换入换出，沿用 Linux 文件系统。**
   所有用户程序以相同地址链接。fork 复制用户窗口及寄存器上下文；调度恢复对应快照。
   指针地址不变，不需要猜测、扫描或重定位栈中的指针。代价是切换时复制内存。
   符合教学优先、性能不敏感的既有约定。
2. 每个进程独立物理地址，修改编译器生成位置无关代码或软件地址翻译。
   执行效率或并发空间使用可能更好，但会扩大编译器、ABI 和用户指针接口的变更范围。
3. 只实现共享地址空间的 vfork 或在内核内置命令解释器。
   不能满足独立 fork 语义及本次明确要求的外部程序加载，不选用。

本草案选择路线 1。内核和进程管理元数据始终常驻，不进入用户快照。
用户程序共享特权级；无硬件内存保护。系统调用检查指针范围，但不能阻止恶意机器码直接写 RAM。

## 地址布局与工具链

初始静态布局如下，最终链接器必须执行边界检查，不依赖注释保证安全：

| 区间 | 用途 |
| --- | --- |
| 0…0x1fffff | 内核镜像、内核数据、启动栈、块缓存及保留区 |
| 0x200000…0x27ffff | 唯一活动用户窗口，512KB，包含用户代码、数据、堆、栈 |
| 0x280000…0x3fffff | 常驻任务元数据、内核任务栈、切换临时栈与预留内存 |
| 0x400000…0x7fffff | 8 份 512KB 用户快照 |

PID 0 是常驻内核 idle，不占用户快照；最多 8 个用户进程，包含 init/shell。
初期采用静态槽分配和有界堆，不把原版 16MB 页表分配器用于这些区域。

内核链接必须给帧缓冲和固定 ABI 网关留出明确保留区；不可再把地址池或可执行代码放进帧缓冲。
内核 BSS 采用支持 32 位地址的布局，必要时内核统一以 --d32 编译，避免低 64KB 容量成为功能上限。

新增用户链接模式：指定用户窗口基址、入口、栈顶和导出 ABI。用户可执行文件采用显式大端头部，
包含 magic、版本、入口偏移、装载字节数、BSS 字节数、栈需求；不冒用原版 x86 a.out。
入口和各段长度必须落在窗口内，并检查溢出与文件截断。

用户程序不能沿用每程序一组低地址跳板的布局。长调用/跳转在调用点构造 32 位目标；
条件跳转在 r13 构造目标后，条件成立时跳到内核保留低区的共用 `jmp r13` 网关。
ALU 操作只写所指定的目的寄存器，目标构造不得写 flags；分支比较结果必须保持有效。
网关地址由同一 ABI 定义提供，内核和用户链接器不得各自硬编码不同值。
这些变化须以超过 64KB 的用户程序分支/调用测试验证，并在游戏内复核。

## 上下文、fork 与调度

新增 SymphonyPlus 汇编桥接对象，保存 r1…r13、sp、flags 和恢复 PC；编译器扩展仅提供必要的
硬件/系统调用入口，C 代码不能假装读取本机寄存器。汇编源加入跟踪例外和统一构建流程。

系统调用桥先在用户上下文保存返回点，再切换到常驻内核栈。
复制或恢复用户窗口时绝不能使用位于该窗口的活动栈。
合作式切换只发生在系统调用边界或显式 yield；不承诺无系统调用死循环的抢占。

fork 的父子分支均从同一调用点返回：父进程得到子 PID，子进程得到 0。
复制整个用户窗口与保存的上下文，继承 cwd、文件描述符和打开文件引用计数；
共享打开文件描述的文件偏移，私有用户内存互不影响。
失败返回负错误码，回滚已取得的槽和引用，不能损坏父进程。

exit 关闭引用、保存退出状态并成为 zombie；waitpid 阻塞/唤醒并回收 zombie。
支持等待指定子进程及任意子进程、WNOHANG、无子进程报错。
复用 Linux task/current 等内核状态，替换 x86 TSS、页表相关路径；不维护一份与 Linux 脱节的伪进程表。
PID 1 负责收养和回收孤儿。shell 退出后由 init 重新启动 shell。

## 系统调用与外部程序

无特权陷阱，采用固定入口的直接调用桥；用户 libc 封装负责负错误码到 errno 的转换。
首版至少提供 fork、execve、exit、waitpid、getpid/getppid、read/write、open/close、
dup/dup2、lseek、stat/fstat、chdir 和必要的终端/进程枚举接口。
其他未实现调用明确返回 ENOSYS，不能返回假成功。

execve 先校验新文件、头部、参数总量和窗口容量；所有失败在破坏旧映像前返回。
成功后替换当前进程用户窗口、清 BSS、构造 argc/argv/envp 栈并进入用户 crt0；PID 保持不变。
用户指针的取字符串、数组遍历和长度计算均做边界及溢出检查。

新增独立用户态源码和最小 libc；sh、ls、cat、echo、forktest 均作为独立可执行文件存放于 /bin。
cd、exit 等影响 shell 本身状态的命令由 shell 内建；其他命令使用 fork/exec/wait。
首版支持空白分词和有界命令行；管道、引号语法、后台作业控制不作为本次验收条件。

## DiskA 与文件系统

为 DiskA 实现同步块设备驱动，用 pload/pstore 搬运 32 位字，经 Linux 块请求/缓存层完成请求。
磁盘容量检查为 8MB；请求失败必须解锁 buffer 并唤醒等待者，不能忙等未实现的 x86 中断。

沿用 Linux 0.11 MINIX v1 文件系统语义。主机镜像构建工具按显式大端字段偏移写入镜像，
不能使用主机 C 结构体或 Python 本机对齐格式直接序列化。
审核目标编译器 struct/short 布局；磁盘结构若与标准 32 字节 inode/16 字节目录项不符，
在磁盘读写边界显式编解码，不能生成只与错误 struct 布局相容的私有 MINIX 变体。

rootfs.bin 包含 /bin、/dev、/etc、/tmp，终端设备节点、/etc/motd 和用于 cat 的示例文本。
首版完成持久文件读写的最小路径，测试创建/读取/重新挂载后读取；无效 magic 和越界 zone 必须报错。
原先 BIOS 磁盘参数读取、分区探测和 x86 硬盘控制器初始化改为平台明确配置。

## 键盘、TTY 与时钟

通过 keyboard 轮询取得事件，按项目已有约定解析按下/释放位。
键码映射、Shift/大小写、Enter、Backspace 的真实硬件表现须在游戏内验证；
键盘驱动与字符行规程分开，避免把游戏键码直接当作完成输入的字符。
实现回显、退格、行缓冲、缓冲满时有界处理、空输入阻塞和输入到来后的唤醒。
console 继续复用现有字符输出，并针对连续滚屏校验 RAM 边界。

读取 time_0/time_1，以轮询方式推进 jiffies；处理低 32 位回绕，不将主机真实时间直接灌入客户机逻辑。
无可运行用户进程时 idle 继续轮询输入和时间。

## 模拟器与可重复验证

保持原 emu_run 接口供旧测试使用；新增带配置的执行接口，可加载磁盘镜像、注入分批键盘事件、
提供确定性时钟，并在运行到等待输入的提示符后通过观测条件结束测试。
交互 CLI 从终端取得输入并转成相同键盘事件；模拟器不能解释 shell 命令或替客户机执行文件操作。
磁盘写回到主机文件须由明确的 CLI 选项控制，测试使用临时镜像副本。

新增测试顺序：

1. 长地址分支、网关保留区及帧缓冲无重叠；汇编桥保存/恢复上下文。
2. fork 父子不同返回值；局部变量、全局变量、栈内指针隔离；多次切换后状态仍正确。
3. wait/exit、孤儿回收、槽耗尽和连续创建回收；文件引用/偏移继承。
4. DiskA 块读写、磁盘结构布局、挂载、目录枚举、文件读取/创建及重挂载。
5. exec 正常加载及拒绝损坏/过大/截断文件，失败时原进程仍能运行。
6. 从 rootfs 启动 sh，分批输入 ls、cat /etc/motd、echo、forktest、未知命令；
   断言真实用户程序输出、退出状态、提示符恢复、退格、重复命令及滚屏。
7. 重建并通过原有全部回归测试；M3 停机验收保留为独立构建配置，默认镜像改为交互启动。
8. 游戏分别加载 kernel.bin/rootfs.bin，确认真实键盘、外部程序和屏幕滚动正常。
